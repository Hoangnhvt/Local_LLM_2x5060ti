# NVFP4 Benchmark Session — 2026-04-27

Model: **Qwen3.6-27B-NVFP4** (compressed-tensors NVFP4)
Hardware: 2× RTX 5060 Ti 16 GB (Blackwell sm_120), PCIe 3.0, no NVLink, no P2P
Stack: vLLM `vllm/vllm-openai:nightly` (v0.19.2rc1.dev220), TP=2, FP8 KV, behind LiteLLM `:4000`

---

## Headline result

| Config | Decode tok/s | Notes |
|---|---|---|
| `--enforce-eager`, max_len=65536 | **8.2** | KV ceiling 53,312 toks |
| **CUDA graphs ON, max_len=32768** | **33.5** | **4× speedup** |

CUDA graphs are the single biggest lever on this hardware. PCIe 3.0 + TP=2 makes per-kernel launch overhead dominate without graphs.

## Final stack config

`stacks/vllm/coder-lg-nvfp4.yml` (key flags):
- `--tensor-parallel-size=2`
- `--max-model-len=${NVFP4_MAX_LEN:-65536}`  (set 32768 in `.env` for fast mode)
- `--max-num-seqs=${NVFP4_MAX_SEQS:-1}`
- `--kv-cache-dtype=fp8`
- `--gpu-memory-utilization=${GPU_MEM_UTIL:-0.92}`
- `--enable-chunked-prefill`
- `--enable-prefix-caching`
- `--reasoning-parser=qwen3`
- `--trust-remote-code`
- (NO `--enforce-eager` — CUDA graphs default ON)

`.env` on remote (current):
```
NVFP4_MAX_LEN=32768
NVFP4_MAX_SEQS=1
GPU_MEM_UTIL=0.92
VLLM_IMAGE_NVFP4=vllm/vllm-openai:nightly
```

## Open ideas to try tomorrow

1. **Bump GPU mem util to 0.95** — vLLM's CUDA-graph profiler hint says 0.92 is effectively 0.89; pushing to 0.95 should recover ~3K KV tokens.
2. **`max_num_seqs=2`** — single-stream is wasting some scheduler slack; small batch may help if memory permits.
3. **Try modelopt+MTP NVFP4 sibling** of this model — model card claims 1.6–1.7× more throughput with MTP.
4. **`--speculative-config`** with a tiny draft model (e.g. Qwen2.5-1.5B AWQ on one card) — but this conflicts with TP=2 and likely not worth the complexity here.
5. **AWQ-int4 comparison** on same Qwen3.6-27B if a checkpoint exists, to decide whether NVFP4 quality/speed trade beats AWQ on Blackwell.
6. **Long-prompt prefill tuning** — `--max-num-batched-tokens` to chunk prefill more aggressively (currently default).
7. **Hermes-3-8B `reason` stack co-resident** — won't fit alongside this NVFP4 model on 32 GB total. Need a stack-switcher script if both wanted.

## Key lessons (added to /memories/vllm-blackwell.md candidates)

- **Don't use `--enforce-eager` on TP > 1 unless absolutely needed** — 4× perf hit on PCIe-only multi-GPU.
- Cudagraph memory profiler (default since 0.21) inflates the apparent VRAM cost; raise `--gpu-memory-utilization` to 0.95 to compensate.
- vLLM 0.19+ removed `--disable-log-requests` from `vllm serve`. Don't add it.
- KV ceiling is independent of nominal `--max-model-len`; check `kv_cache_utils.py` log line for the real cap.

```

python3 scripts/bench_toks.py --runs 1 --max-tokens 256 --no-think --repeat-prompt 1200
```
